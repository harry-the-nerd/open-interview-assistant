Why it feels different

Built for live interviews, not demos

Every design choice protects your focus — the panel helps you speak clearly without hijacking the tools you’re already using.

No screen recording

A tiny Chrome extension reads the text of the page — cleaner input than pixels, and zero macOS screen-recording permission.

Mouse pass-through

The panel ignores the mouse completely. Hovering and clicking fall through to your editor or browser — it can never steal focus.

Keyboard-only controls

No buttons. No chrome. Every action is a shortcut — send page, scroll answer, dock, hide, opacity, thinking effort.

Interview-arc answers

Responses follow how strong candidates actually talk: summary → restate → clarify → approach → code → walkthrough.

Hidden from screen share

Uses Electron content protection so the overlay does not appear in recordings or screen shares — only you see it.

Adaptive thinking

Claude Sonnet decides how long to reason. Cycle effort with a shortcut when you need speed or maximum care.

Pinned summary

Binary-search the partition point

Cut the shorter array so left halves and right halves satisfy the median invariant.

Time O(log min(m,n)) Space O(1)
Ask first

Clarifying questions

Empty arrays? Even vs odd total length? Are inputs always sorted? Integer-only values?

Approach

Why not merge?

Linear merge is O(m+n). Interviewers want the log-time cut on the shorter array.

Walkthrough

nums1=[1,3], nums2=[2]

Partition lands with left max=1,2 and right min=3 → median 2.

Trust model

Local-first. Least privilege. Defended in depth.

The extension only talks to your machine. The model only sees page text you explicitly send.

What this project does

Designed so the overlay can help without becoming another surveillance surface.

  • Page text only — no screenshots, no continuous capture
  • activeTab + scripting — reads the current tab when you press the shortcut
  • Loopback-only server on 127.0.0.1 with token auth, origin checks, body caps, rate limits
  • Content protection — panel hidden from screen shares and recordings
  • No broad host access — no list of interview sites, no “read all websites” permission

What it deliberately avoids

Common patterns in “AI interview copilots” that create risk and friction.

  • No always-on microphone — it never listens and never records audio
  • No screen-recording prompts — text beats pixels for coding questions anyway
  • No mouse-stealing UI — overlays that grab clicks break your flow mid-problem
  • No cloud account required for the OSS app — bring your own Anthropic API key
  • No silent re-pairing forever — after first claim, recovery is a deliberate keystroke

Get started

Clone, key, run, load unpacked

Local Electron app + a plain Chrome extension. No build step for the extension.

terminal setup 
# clone
git clone https://github.com/harry-the-nerd/open-interview-assistant.git
cd open-interview-assistant

# install + configure
npm install
echo 'ANTHROPIC_API_KEY=sk-ant-...' > .env

# run the overlay
npm run dev

Load the extension once

  1. Open chrome://extensions and enable Developer mode.
  2. Click Load unpacked and select the repo’s extension/ folder.
  3. With the app running, pairing happens automatically on install, browser startup, or the first ⌘⇧U.
  4. If the shortcut collides, rebind it at chrome://extensions/shortcuts.
